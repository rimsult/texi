# texi — офлайн-тренажёр английской лексики (PWA)

**Слова, которые запомнятся.** Модульное PWA для изучения английских слов уровней **A1–C2**.
Бюджет — 0 ₽: только open source, открытые данные и бесплатные тарифы, без LLM API.

* **Слово → определение** — видите английское слово, выбираете верное из трёх определений.
* **Определение → слово** — видите определение, выбираете слово из трёх.
* **Вставьте слово** (раздел «Дополнительно») — пример с пропуском, выбираете слово из трёх в нужной
  форме (*ate*, *colleges*). Каждый неверный вариант проверен офлайн-моделью BERT: в пропуск он
  подходить не должен. 5 696 вопросов в общем наборе (A1 700 · A2 854 · B1 1 497 · B2 1 732 · C1 582 ·
  C2 331) и 186 в техническом.
* **Определения по уровню.** Для A1–B1 определение берётся из учебного словаря Simple English
  Wiktionary (написан базовой лексикой: *bicycle* → «a vehicle with two wheels; you use your legs to
  make it move»), для B2–C2 — точное определение WordNet. Выбор измеряемый: доля слов выше уровня
  ученика в определениях упала с 39 до 20 % для A1, с 19 до 8 % для A2 и с 8 до 3 % для B1.
* Для A1–A2 можно включить русские определения, с B1 — только английские. Русское определение — это
  **полное определение, переведённое с английского** двумя офлайн-моделями машинного перевода
  (*dog* → «животное, которое…», а не «собака»); короткий перевод слова показывается после ответа.
* **Разбор после ответа.** При ошибке видно, что именно вы выбрали: «Вы выбрали определение слова
  *wheel* (колесо)» или «Вы выбрали *wheel* — означает: …». После любого ответа — перевод слова,
  пример (для A1–A2 — с переводом), синонимы, а у русского определения — английский оригинал.
* **Уровень сложности: Обычный | Сложный.** В сложном режиме неверные варианты берутся из той же
  смысловой группы, что и слово (*transistor* — *capacitor*, *resistor*; *breakfast* — *dinner*, *lunch*),
  но никогда не синонимы и не слова с тем же переводом.
* **Набор слов: Общая | Техническая лексика.** Общая — 11 949 слов: списки CEFR-J и Octanove плюс
  2 817 частотных слов WordNet уровней B2–C2. Техническая — 1 260 терминов для студентов
  технических вузов; **области выбираются кнопками** (ИТ, электротехника, физика, математика, химия,
  инженерия — одна, несколько или все), прогресс отдельный.
* **Интерфейс на русском или английском** — переключатель RU / EN в шапке.
* Иконка — робот texi: во вкладке браузера, на домашнем экране (PWA, iOS) и в `Texi.html`.
* **Готовый файл `Texi.html`** — всё приложение и весь контент в одном файле (~3,6 МБ): открывается
  двойным кликом, без установки, сервера и интернета.
* Работает полностью офлайн (Service Worker кэширует приложение и все 12 пакетов контента).
  Прогресс хранится в IndexedDB, а при появлении сети уходит на сервер (идемпотентно, без конфликтов).
* Регистрации нет: устройство получает анонимный UUID.

## Готовый файл (без установки)

`Texi.html` — самодостаточная сборка: код, шрифты и все пакеты (сжатые gzip) внутри одного HTML.

* Открыть двойным кликом в Chrome, Edge, Яндекс Браузере или Firefox — сервер и интернет не нужны.
* Прогресс и настройки хранятся в браузере (IndexedDB), на этом компьютере и в этом браузере;
  синхронизации с сервером нет. Если браузер запрещает хранилище для локальных файлов (бывает в Safari),
  приложение всё равно работает, а в статусе написано «Прогресс до закрытия вкладки».
* Собрать заново: `npm run build:standalone` → `apps/web/dist-standalone/Texi.html`.

## Быстрый старт

Нужны Node 24, Python 3.11+ (только для пересборки контента), опционально Docker.

```bash
npm ci
npm run dev                  # http://localhost:5173 — работает и без API (прогресс локально)
```

С API и базой:

```bash
docker compose up -d db                                   # PostgreSQL 16
DATABASE_URL=postgres://lexi:lexi@localhost:5432/lexi npm run start -w @lexi/api   # миграции + сидинг автоматически
VITE_API_URL=http://localhost:8787 npm run dev
```

Без `DATABASE_URL` API работает с in-memory хранилищем (удобно для разработки и E2E).

## Тесты

```bash
npm run test:pipeline        # pytest: 225 тестов, включая контракт реальных пакетов
npm run test:unit            # vitest: core 112 · web 50 · api 37 (12 PG-тестов при TEST_DATABASE_URL)
npm run test:e2e             # сборка (PWA + Texi.html) + Playwright: 10 сценариев (десктоп + мобильный)
npm run typecheck
npm test                     # всё сразу
```

PG-тесты: `TEST_DATABASE_URL=postgres://postgres@localhost:5432/lexi_test npm run test:unit`.
Если Chromium установлен не через Playwright: `PLAYWRIGHT_CHROMIUM_PATH=/path/to/chromium npm run test:e2e`.

Что проверяют тесты (кратко):

* **Пайплайн:** шаблоны генерации, правила дистракторов, фильтрация переводов, разбор Simple
  Wiktionary и выбор определения по уровню, выбор перевода (взаимная оценка движков, глоссарий,
  отбраковка обрезанных и повторяющихся вариантов), мини-сборка end-to-end и *контракт реальных
  пакетов* — хэши манифеста, каждое слово ровно в одном уровне, `ru` только для A1–A2, одно определение
  на язык, доля учебных определений (A1/A2 > 60 %, C1/C2 < 20 %), перевод примеров только для A1–A2,
  >50 000 проверок дистракторов (та же часть речи, CEFR ±1, другая семантическая группа, не синоним,
  нет общих переводов), ни одно определение не содержит само слово; для сложного режима — та же
  смысловая группа, но не синоним, не гипероним, без общих значений и переводов, варианты различаются
  и между собой; технический набор — каждое слово в своём наборе и области, счётчики по областям.
* **Ядро:** каждый вопрос из реальных пакетов (оба набора × 6 уровней × 2 сложности × 2 тренажёра ×
  2 языка) собирается, проходит клиентскую валидацию и не смешивает языки; в сложном режиме все три
  варианта из одной группы; фильтр по техническим областям; разбор ошибки (чьё это определение) и
  пример/синонимы после ответа; новый плагин-тренажёр работает с неизменённым движком сессий.
* **Web:** IndexedDB-хранилище, очередь синхронизации (батчи, повторы, backoff, офлайн), загрузка
  пакетов уровня ±1 для каждого набора, встроенные пакеты однофайловой сборки, полный UI-сценарий
  (оба набора, кнопки областей, сложный режим, разбор ответа), переключение интерфейса RU/EN, клавиатура.
* **API:** схема запроса, идемпотентность при конкурентных повторах, ограничения в схеме БД
  (триггер «ru только A1–A2», минимум 2 дистрактора, префикс `tech:`), пакеты обоих наборов из БД
  равны статическим (вместе с примерами, их переводами и синонимами), набор и сложность сохраняются в событиях.
* **E2E:** сессия A1 с русскими определениями → разбор с переводом и примерами → результаты →
  синхронизация; B2 только английский; **приложение продолжает работать после остановки веб-сервера и
  отключения сети**, ответы копятся в очереди и уходят на сервер при возвращении сети; техническая
  лексика в сложном режиме (варианты — ближайшие соседи из пакета); английский интерфейс и одна
  область сохраняются после перезагрузки; **`Texi.html` открывается с диска без сети**, сохраняет
  прогресс после перезагрузки и не делает ни одного сетевого запроса; на мобильном нет горизонтального скролла.

## Контент

```bash
data-pipeline/scripts/fetch_sources.sh     # скачать открытые источники (~26 МБ) + WordNet для NLTK
pip install -r data-pipeline/requirements.txt
npm run content:build                      # ~3–10 мин → apps/web/public/packs/*.json + data-pipeline/out/
# необязательно — только если появились новые тексты без перевода/проверки в кешах:
data-pipeline/scripts/fetch_mt_model.sh    # Argos en→ru (~100 МБ) + FAIR WMT19 en→ru (~1,1 ГБ) + BERT (~440 МБ), CPU
pip install -r data-pipeline/requirements-mt.txt
```

Без моделей сборка берёт русские определения из кеша `data-pipeline/data/mt_en_ru.json`, а проверки
«Вставьте слово» — из `data-pipeline/data/gap_lm.json` (`--no-translate` — явно запретить запуск
моделей; результат тот же). Тексты, которых нет в кеше, остаются без русского варианта.
`fetch_mt_model.sh --argos-only` скачивает только маленькую модель (качество ниже: нет второго движка).
Необязательные внешние движки — с вашим ключом: `GOOGLE_TRANSLATE_API_KEY` (Google Cloud Translation,
500 тыс. символов/мес. бесплатно) или `DEEPL_AUTH_KEY` (DeepL API Free); см. «Сравнение переводов».

Пакеты и `data-pipeline/out/` коммитятся в репозиторий, поэтому Vercel и Render не нуждаются в Python.
После пересборки API сам пересидирует базу при старте (если изменилась версия контента).

Правила качества:

* Определения: WordNet (качество 0,9) → Wiktionary (0,8 / 0,7) → строгие шаблоны
  (`source: "generated"`, качество ≤ 0,5, например *quickly* → «in a quick manner»).
* **Определение по уровню** (`adapt.py`): для слов A1–B2 кандидат — определение Simple English
  Wiktionary (`source: "simple"`, учебный словарь, написанный базовой лексикой). Оно заменяет WordNet,
  только если в нём заметно меньше слов выше уровня ученика (по CEFR-спискам и частотности) и оно
  описывает то же значение: основное значение статьи сверяется с синсетом WordNet по
  информативным словам; для редких значений (*watch* как «вахта») слово остаётся с WordNet. Из
  учебного определения убирается само слово («A bicycle is …» → «a vehicle …»), а фразы в стиле
  Cobuild, где слово стоит внутри («If you carry something, you lift it up and move it…»),
  **переписываются в словарную форму** по части речи (`rewrite.py`): «to lift something up and move
  it…», «when something is ___, it is not easy» → «not easy», «if someone is ___, they know how…» →
  «someone who knows how…». Если главную часть переписать нельзя — берётся определение WordNet;
  пропусков `___` в определениях нет (проверяется в пайплайне и в ядре). Итог — доля слов выше уровня в
  определениях A1 39 % → 20 %, A2 19 % → 8 %, B1 8 % → 3 %, B2 5 % → 2 %. Каждое решение записано в `data-pipeline/out/adapt_log.json`.
* Русские определения (`source: "machine"`, качество 0,7) — перевод выбранного английского
  определения **двумя офлайн-моделями**: Argos Translate en→ru (OPUS, CTranslate2) и FAIR WMT19 en→ru
  (победитель WMT19, transformers) — без API, без LLM и без оплаты. Каждая модель выдаёт несколько
  гипотез для 1–2 формулировок (глаголам добавляется «to …»), затем **каждая модель оценивает каждую
  гипотезу** (лог-вероятность при принудительном декодировании) и выигрывает гипотеза с лучшей суммой:
  ошибка одной модели («concerts» → «консилиумах», обрезанный хвост, потерянное второе предложение)
  маловероятна для другой. Гипотеза принимается только без латиницы, без повторов («силой или силой»),
  с разумной длиной и без выдуманного пола («взрослый мужчина женского пола»); два синонима,
  переведённые одним словом, склеиваются («приятное, приятное» → «приятное»); вариант, потерявший
  предложение примера или сжавший определение в одно слово («day after today» → «послезавтра»),
  проигрывает полному; небольшие поправки — нужной форме (инфинитив, прилагательное, именительный
  падеж), переводу слова из Wiktionary (глоссарий) и штраф за повтор корня («планеты с планетами»).
  Нет годного перевода — у слова нет русского варианта.
  Переводы закешированы в `data-pipeline/data/mt_en_ru.json` (в репозитории), поэтому сборка
  воспроизводима без моделей; модели нужны только для новых определений (`scripts/fetch_mt_model.sh`).
* Примеры: пример WordNet или Simple Wiktionary (самый короткий хороший) показывается после ответа,
  для A1–A2 — с машинным переводом; синонимы — до трёх частотных однословных синонимов значения.
* Перевод слова (*собака, пёс*) — из Wiktionary/WikDict, ранжирован по частотности; поле `translation`
  есть только в пакетах A1–A2 и показывается после ответа на русский вопрос.
* У каждого определения есть `lang: "ru" | "en"`; русские — только A1–A2 (проверяется в пайплайне,
  в ядре, в zod-схеме API и триггером в PostgreSQL).
* Дистракторы: та же часть речи, уровень ±1, другая семантическая группа (lexname WordNet / кластер
  прилагательных), не синонимы, без общих переводов, не слишком похожие по смыслу (Wu-Palmer < 0,8).
  В русском режиме дополнительно: определение варианта не содержит перевод загаданного слова и
  наоборот («молодая собака» — *puppy* — никогда не стоит рядом с *dog*).
  Если подобрать два не удалось — вопрос получает `needs_review` и **никогда** не показывается
  (`data-pipeline/out/needs_review.json`, `GET /v1/review`).
* Сложный режим: отдельный список `hard` у вопроса — та же часть речи, уровень ±1 и та же смысловая
  группа (lexname WordNet; у прилагательных — «семья» антонимов: *big* ↔ *small*), отсортированный
  по близости. Запрещены синонимы, общие значения и переводы, гиперонимы/гипонимы, одинаковые
  определения и слишком близкие слова (Wu-Palmer ≥ 0,93, у глаголов ≥ 0,83); варианты не должны
  совпадать и между собой. Клиент берёт 2 из 3 ближайших. Если группа слишком мала — слово в сложном
  режиме не показывается (на карточках уровней видно, сколько слов доступно).
* В одной тренировке определения на одном языке: в режиме «Русские» слова без русского определения
  пропускаются (их можно учить в режиме English).
* **«Вставьте слово»** (`gapfill.py`): пропуск — само слово в примере (в найденной форме: *ate*,
  *colleges*), варианты — слова той же части речи, уровня ±1 и другой смысловой группы в **той же
  форме** (LemmInflect: *slept*, *drank*; у существительных без нормального множественного числа,
  как *information*, формы во множественном нет). Не синонимы, без общих переводов, не гиперонимы, не
  встречаются в предложении. Каждый вариант проверяет офлайн-модель BERT: если он тоже правдоподобен
  в пропуске — отклоняется (пороги — в docs/ARCHITECTURE.md). Наречия не используются.
* Ругательства, сексуальная и оскорбительная лексика (`text.SENSITIVE`: *goddamn*, *rape*, *idiot*…)
  изучаются как обычные слова, но никогда не подставляются неверным вариантом в чужой вопрос.
* Порядок перебора кандидатов — хеш пары «вопрос | кандидат», поэтому новые слова в словаре не
  перетасовывают варианты остальных вопросов; две сборки подряд дают побайтно одинаковые пакеты.

### Техническая лексика

Набор собирается только из открытых данных (`data-pipeline/lexi_pipeline/technical.py`):

1. Кандидаты — слова с тематической меткой WordNet (*computer science*, *physics*, …), с пометкой
   области в Wiktionary (*(computing)*, *electronics:* …) и гипонимы ~110 технических корневых понятий
   WordNet (*electronic device*, *plane figure*, *chemical element*, *mechanical device*, …), если это
   основное значение слова. Широкие корни (*number*, *compound*, *fastener*) дают только слова, которых
   нет среди бытовой лексики A1–B1.
2. Ядро каждой области — ~390 вручную отобранных терминов первых курсов (`SEEDS`: *velocity*,
   *torque*, *eigenvalue*, *compiler*, *crankshaft* …) с закреплённым значением WordNet: WordNet часто
   хранит их вне «технических» веток (*velocity* — это «rate»), и правила их бы пропустили.
3. Отсев: стоп-лист бытовых слов и частотность wordfreq (Zipf ≥ 2,0; для ядра ≥ 1,0).
4. Уровень — из CEFR-списков, если слово там есть (282 слова), иначе оценивается по частотности с
   порогами, откалиброванными на тех же списках (978 слов, не ниже B1).
5. Определение — именно техническое значение WordNet (и его машинный перевод для A1–B1); перевод
   слова берётся из Wiktionary, только если его значение совпадает с техническим.

### Расширение общей лексики

CEFR-списки заканчиваются на ~9,5 тыс. слов, поэтому общий набор дополнен
(`data-pipeline/lexi_pipeline/extra.py`) 2 817 словами WordNet, которые: часто встречаются в
современном английском (wordfreq, Zipf ≥ 2,8), размечены в корпусе SemCor (счётчики значений
WordNet — отсекают словарные редкости), не являются именами, формами других слов (*made*, *longer*),
сленгом, грубой или устаревшей лексикой. Уровень — по частотности с теми же калиброванными порогами,
не ниже B2 (B2 1 020 · C1 1 326 · C2 471). Специальные термины уходят в технический набор.

### Сравнение переводов

Проба на 250 текстах уровней A1–B1 (определения и примеры, `data-pipeline/probe/`, отчёт —
`probe/report.html`): текущий перевод (ансамбль Argos + FAIR WMT19) против Google Translate.

| | Без замечаний автопроверок | Лучше по ручной оценке |
|---|---|---|
| Текущий (Argos + WMT19, офлайн) | 209 / 250 | ≈ 6 % |
| Google Translate | 214 / 250 | ≈ 38 % |
| Одинаково хорошо | | ≈ 56 % |

Google заметно естественнее на длинных определениях и идиомах, но требует ключа (Google Cloud
Translation: 500 тыс. символов/мес. бесплатно, нужна привязка карты). DeepL через DLX с серверов
облака не работает (429 — блокировка IP), DeepL API Free тоже требует аккаунт. Поэтому по умолчанию
остаётся офлайн-ансамбль, а с ключом `GOOGLE_TRANSLATE_API_KEY` (или `DEEPL_AUTH_KEY`) пересборка
добавляет внешний движок в ансамбль: его варианты оцениваются теми же моделями, и в кеш попадает лучший
(для текстов, которых ещё нет в кеше; чтобы перевести всё заново, удалите `data/mt_en_ru.json`).

## Деплой за 0 ₽

1. **База — Supabase Free.** Создайте проект, скопируйте строку подключения
   (Project Settings → Database → *Session pooler*, порт 5432). Таблицы создадутся сами.
2. **API — Render Free.** New → Blueprint → репозиторий (используется `render.yaml`).
   Укажите `DATABASE_URL` и `CORS_ORIGIN=https://<ваш-проект>.vercel.app`. При старте выполняются
   миграции и сидинг (под `pg_advisory_lock`, так что несколько экземпляров не мешают друг другу).
   Проверка: `GET /health`.
3. **Фронтенд — Vercel Hobby.** Импортируйте репозиторий (настройки берутся из `vercel.json`),
   добавьте `VITE_API_URL=https://<api>.onrender.com`.

Примечания:

* Бесплатный Render засыпает после 15 минут простоя, первый запрос идёт ~30–60 с. Для приложения это
  не критично: оно offline-first, а очередь синхронизации ретраит с backoff.
* У Railway нет постоянного бесплатного тарифа (только пробный кредит) — API там тоже запустится
  (`apps/api/Dockerfile`), но рекомендуемый вариант за 0 ₽ — Render.
* Бесплатный Postgres у Render удаляется через 30 дней, поэтому база — в Supabase
  (Free-проект приостанавливается после недели без запросов; регулярная синхронизация это предотвращает).
* Фронтенд работает и без API: если `VITE_API_URL` не задан, прогресс просто остаётся на устройстве.

## Ограничения MVP и дальнейшие шаги

* Служебные слова (артикли, предлоги, местоимения) исключены — для них нужен тренажёр грамматики.
* Русские определения — машинный перевод: две модели и взаимная оценка заметно снижают число грубых
  ошибок, но неуклюжие или неточные формулировки встречаются (их можно поправить прямо в
  `data/mt_en_ru.json`). ~1 % слов A1–A2 без годного перевода доступны только в режиме English.
* Учебные определения Cambridge/Oxford/Longman проприетарны, поэтому учебный источник — Simple
  English Wiktionary: он покрывает не все слова и не все значения; там, где он не проще или описывает
  другое значение, остаётся WordNet.
* Уровни B2–C2 для слов вне CEFR-списков (общий и технический наборы) оценены по частотности —
  это приближение, а не экспертная разметка.
* Технический набор и выбор значения — эвристика по открытым данным: отдельные термины могут
  оказаться не в той области или с общим, а не техническим переводом. В сложном режиме близкие
  варианты отобраны строгими правилами, но спорные пары всё же возможны — их можно отправить в `needs_review`.
* Однофайловая версия хранит прогресс только в браузере, без синхронизации между устройствами.
* «Вставьте слово»: примеры WordNet часто короткие фразы («A dim light beside the bed.»), и в них
  неверный вариант иногда звучит допустимо, хотя языковая модель считает его маловероятным; спорный
  вариант убирается вручную — перенести его из `ok` в `x` у предложения в `data/gap_lm.json`. Наречия
  не используются.
* Следующие тренажёры уже обозначены в реестре: аудирование (Web Speech API, бесплатно),
  грамматика (CEFR-J Grammar Profile).
* Аккаунты/перенос прогресса между устройствами: события уже привязаны к `deviceId`, достаточно
  добавить связку устройств с пользователем (например, Supabase Auth).
